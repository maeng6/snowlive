# 같이타요 & 라이브 배틀/레이드 기획

> 작성: 2026-10 · 스노라이브(Snowlive)
> 핵심 자산: **라이브온 = "지금 진짜 이 스키장에서 타고 있다"는 서버 검증된 실시간 증명.**
> 이 실시간성을 축으로 두 개의 기능 기둥을 세운다.
>
> - **기둥 A — 같이타요(오프라인 합류):** 같은 리조트에 라이브온 중인 사람끼리 현장에서 만나 같이 탄다.
> - **기둥 B — 라이브 배틀/레이드(온라인 데이터):** 서로 다른 리조트에서 각자 타는 사람들이 방에 모여 실시간 라이딩 데이터로 **대결(경쟁)** 하거나 **공동 목표(합동)** 를 달성한다.
>
> 두 기둥은 **라이브온 검증 · 방(room) · 실시간 데이터 · 채팅 · 보상**을 공유한다.

---

## 0. 왜 스노라이브만 가능한가 (해자)

- 라이브온은 GPS·지오펜스로 **현장 존재가 서버에서 검증**된다 → 가짜·노쇼·시간낭비를 구조적으로 차단.
- 라이딩 기록(점수·거리·속도·시간·수직하강)이 **실시간으로 들어온다** → "주장"이 아니라 **데이터로** 매칭·대결·협동이 가능.
- 라이브오프(퇴장) 시 자동으로 모집·대결에서 빠진다 → 유령방 방지.

# 기둥 A — 같이타요 (같은 리조트 · 오프라인 합류)

## A-1. 한 줄 컨셉
> **"지금 이 스키장에 라이브온 중인 사람끼리만, 지금 당장 같이 탈 사람을 찾는다."**

## A-2. 사용자 유형
1. 혼자 온 사람 — 같이 탈 사람 찾기
2. 더 타고 싶은 사람 — 일행이 쉬거나 실력차로 따로 타고 싶을 때
3. 실력 맞춤 원하는 사람 — "중상급 카빙 같이 팔 사람"
4. 초보 메이트 — "초보끼리 천천히"

## A-3. 핵심 플로우
**① 모집자(비콘 켜기):** 라이브온 상태 → `같이타요` → 비콘 켜기
- 종목(스키/보드) · 실력(초/중/상) · 분위기(빡세게/설렁설렁/사진) · 모집 인원(2~N) · 만날 곳 · 한 줄 메시지
- 켜는 순간 **내 스키장 같이타요 지도/리스트에 노출**

**② 참여자(둘러보기):** 라이브온 상태 → 우리 스키장에서 열린 비콘 목록(거리/실력순)
- 카드 예: "비발디 레드 · 보드 · 중급 · 2명 모집 · '카빙 팔 사람'"
- [참여 신청] → 모집자 수락 시 **그룹 채팅방 생성 + 서로 실시간 위치 공개**

**③ 만남:** 리스폰포인트/리프트 베이스/슬로프 폴리곤(기존 자산)에서 합류. 지도에 서로의 실시간 위치 핀.

## A-4. 매칭·필터
- 필수: 같은 리조트(지오펜스) + 라이브온 중
- 선택: 종목 / 실력 / 분위기 / 인원
- 스마트 추천(v2): 평균속도·주력 슬로프 비슷한 사람 우선

## A-5. 안전·신뢰·프라이버시
- **라이브온 필수** = 현장 검증(가짜 차단)
- 합류 전엔 대략 위치(슬로프 구역)만, **수락 후에만 정밀 위치 공개**(opt-in)
- 신고·차단·강퇴, 노쇼/신고 누적 시 비콘 제한
- 성별 공개/필터 옵션, 미성년 보호
- **친구/크루 우선 토글** — 모르는 사람 부담되면 친구·크루에게만 노출
- 단체 안전문구 자동 삽입(안전장비·보험 본인 책임)

## A-6. 종료·만료
- 라이브오프 시 비콘 자동 종료, 채팅방은 N분 유지 후 보관
- 무응답 비콘 자동 만료

# 기둥 B — 라이브 배틀 / 레이드 (크로스 리조트 · 데이터 합동/경쟁)

## B-1. 한 줄 컨셉
> **"서로 다른 스키장에서 각자 타고 있어도, 한 방에 모여 실시간 데이터로 대결하거나 함께 목표를 깬다."**
> 물리적으로 떨어져 있어도 **데이터 공간에서 같이 탄다.**

## B-2. 두 가지 모드

### (1) 경쟁 모드 — 대결/배틀
방 멤버들이 **정해진 시간/범위 동안 지표로 겨룬다.**
- 지표(택1): **합산 점수 · 총 거리 · 수직하강(누적 고도) · 최고속도 · 라이딩 횟수**
- 실시간 리더보드가 각자 라이딩 데이터가 들어올 때마다 갱신
- 포맷:
  - **1:1 라이벌 배틀** — 친구 소환("이거 너 아니야?" 바이럴과 연결)
  - **소규모 방 배틀** (2~8명)
  - **크루 vs 크루 팀전** (기존 크루 재사용, 팀 합산)
  - 공개 리그/토너먼트 (v2)

### (2) 합동 모드 — 협동/공동목표(레이드)
방 멤버 기록을 **하나의 목표에 합산**한다.
- 예: "우리 방 오늘 합계 **100km** 타기" / "합계 **10,000점**" / "다같이 수직 **50,000m** 하강"
- 모두가 탈수록 진행바가 차오르고, 달성 시 **방 전체 보상**
- 공동 레이드/보스레이드 감성 → 혼자 타도 "같이 깨는" 느낌

## B-3. 방(챌린지) 생성 플로우
호스트가 설정: **모드(경쟁/합동) · 지표 · 범위 · 인원 · 보상 · (합동이면) 목표치**
- **범위(window) 옵션:**
  - `LIVE_WINDOW` — 지금부터 30분/1시간 실시간 단판
  - `TODAY` — 오늘 자정까지
  - `WEEKEND` / `SEASON` — 주말·시즌 롱런
- 참가 조건: **라이브온 중**(실시간 단판) 또는 **해당 기간 라이딩 기록 보유**(롱런)
- 초대: 링크 공유 / 친구·크루 초대 / 공개방

## B-4. 실시간 집계 (동작 원리)
1. 각 멤버가 라이딩 → **commit-ride**로 기록(점수·거리·속도·수직하강·시간)이 서버에 들어온다(기존 파이프라인).
2. 챌린지 window 안 + 라이브온 + 폴리곤 내 기록만 집계 대상.
3. 멤버별 지표 재계산 → **방 리더보드/진행바를 Firestore 실시간으로 push**(배너·위치처럼 longpolling 적용).
4. 순위 역전/목표 근접 시 **푸시 알림**("OO가 너를 제쳤다!", "목표까지 2km!").

## B-5. 공정성(서로 다른 리조트 보정)
리조트마다 슬로프 난이도·길이가 달라 **완전 공정은 불가능 → 캐주얼 전제 + 선택적 보정.**
- 기본 추천 지표 = **점수(score)**: 이미 거리·경사·속도 가중으로 산출돼 리조트 편차를 어느 정도 흡수.
- **핸디캡 옵션**(친선전): 실력 티어/시즌점수 기반 가중.
- **단위 정규화 옵션**(v2): 리조트별 평균 대비 상대값, 또는 "런당 점수".
- **치팅 방지(기존 자산 재사용):** 라이브온+폴리곤 내만 집계 · `speed_cap`으로 GPS 스파이크 방어 · window 밖 기록 제외 · is_test 격리.

## B-6. 보상 (기존 자산 연계)
- **뱃지 / 방 승리 기록 / 라이벌 전적**
- **시즌 랭킹 포인트 가산**(UserSeasonScore 집계 패턴 재사용)
- **눈송이상점 재화**(기존 '눈송이상점' 연계) — 승리·목표달성 보상, 아이템 교환
- **베팅은 현금 금지, 재화(눈송이)로만** — 법적 리스크 차단

## B-7. 소셜 / 바이럴
- 순위 역전 푸시 → 재진입·세션 연장
- **결과 공유카드**(데이터랩 공유카드 재사용): "오늘 방 배틀 🏆 1등 / 합계 120km 레이드 클리어"
- "이거 너 아니야?" 인스타 시리즈와 직접 연결(친구 소환 → 1:1 배틀)
- 라이딩 후 같이한 사람 친구 추가 → **친구 그래프 성장**

## 공통 설계 (두 기둥 공유)

### 재사용하는 기존 자산
| 요소 | 재사용 |
|---|---|
| 현장 검증 | 라이브온 + 지오펜스(리조트 소속 판정) |
| 실시간 위치 | `User_live_position` + 실시간 위치공유 지도(리조트 그룹핑·슬로프 폴리곤 배경) |
| 라이딩 데이터 | `Ranking_record_2627`(점수·거리·속도·수직하강·소요시간 `duration_s`) + commit-ride |
| 채팅 | 라이브톡/오픈채팅(crew_id·secret 구조) 그룹방화 |
| 실시간 동기화 | Firestore(배너·오픈채팅처럼 autoDetectLongPolling 적용) |
| 팀전 | Crew |
| 보상 재화 | 눈송이상점 |
| 집계 패턴 | UserSeasonScore/CrewSeasonScore 증분 집계 |

### 데이터 모델(초안)
```
RideTogetherBeacon   # 기둥 A
  host, resort, slope_area, type(ski/board), skill, mood, capacity,
  status(open/closed), visibility(public/friend/crew), expires_at

BeaconMember
  beacon, user, status(신청/수락/합류/이탈)

Battle               # 기둥 B
  host, mode(COMPETE/COOP), metric(SCORE/DISTANCE/VERTICAL/TOPSPEED/COUNT),
  scope(LIVE_WINDOW/TODAY/WEEKEND/SEASON), start_at, end_at, status,
  is_cross_resort(bool), target_value(합동 목표), reward, visibility

BattleMember
  battle, user, resort_at_join, live_metric, rank, contributed_value
```
- 집계: commit-ride가 window 안에 들어오면 해당 battle의 member metric 증분 갱신 → Firestore 방 문서(leaderboard/progress) 갱신.

### 수익화
- **무료 코어**(네트워크 효과 우선): 비콘·참여·기본 배틀 무료
- **프리미엄/시즌권:** 고급 필터(실력·성별), 비콘 상단 노출, 배틀 무제한·커스텀 지표·크루전·핸디캡, "지금 우리 스키장 라이브온 N명" 히트맵, 합동 궤적·배틀 결과 저장

## MVP vs v2

### MVP (빠르게)
- **기둥 A:** 라이브온 필수 → 비콘 켜기(종목·실력·인원·한줄·만날곳) → 우리 스키장 비콘 리스트 → 참여 수락 → 라이브톡 그룹방 + 지도 위치공유 → 라이브오프 자동종료 · 신고/차단
- **기둥 B:** 친구 1:1 또는 소규모 방 **배틀(지표=점수, 범위=TODAY)** → commit-ride 실시간 집계 → 방 리더보드 → 결과 공유카드

### v2
- 스마트 추천, 성별/친구 우선 필터, 합동 레이드·보스레이드, 크루전/리그/토너먼트, 핸디캡·정규화, 히트맵, 프리미엄, 눈송이 보상 심화

## 리스크 & 대응
| 리스크 | 대응 |
|---|---|
| 안전/이상행동(A) | 라이브온 검증 + 신고·차단 + 친구/성별 필터 + 안전문구 |
| 빈 리스트/초기 유저풀 | 주말·인기 리조트부터, "지금 N명 라이브온" 수치 노출, 친구·크루로 시드 |
| 노쇼(A) | 라이브온 종속 + 노쇼 패널티 |
| 리조트 간 불공정(B) | 점수 지표 기본, 핸디캡/정규화 옵션, 캐주얼 전제 |
| 치팅(B) | 라이브온·폴리곤 내만 집계, speed_cap, window 제한, is_test 격리 |
| 사행성(베팅) | 현금 금지, 눈송이 재화로만 |
