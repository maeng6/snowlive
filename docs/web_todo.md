## 1. 서버 작업 필요 (2건)

### 1-1. 크루별 크루톡 조회 API

크루톡은 라이브톡과 같은 테이블에 저장되는데, **크루 단위로 읽어올 방법이 없습니다.**

실측 결과 (2026-10-06):

```
POST /api/livetalk/list/   {"crew_id": 334}   →  30건
POST /api/livetalk/list/   {}                 →  30건   ← 결과가 같음
```

돌아온 30건의 `crew_id`가 전부 `null` 입니다. 서버가 `crew_id` 파라미터를 **받기만 하고 무시**한 채
전체 라이브톡을 돌려줍니다. 크루 전용 경로는 404입니다.

반대로 **쓰기는 정상입니다.** 업로드 시 `crew_id`와 `secret`을 함께 보내고 서버가 저장하며,
응답 필드에도 `crew_id` · `secret`이 이미 있습니다. **데이터는 쌓이는데 읽는 길만 없는 상태**입니다.

**요청 사항**

| | 내용 |
|---|---|
| ① 필터 | `livetalk/list/`가 `crew_id`를 받으면 그 크루 글만 반환 |
| ② 노출 규칙 | `secret=true` 글은 **요청자가 그 크루원일 때만** 반환 |

②는 화면 구성이 아니라 정보 노출에 관한 것입니다.
크루톡 올리기의 `전체공개` 스위치를 끄면 `secret=true`로 저장되는데, 지금은 누가 볼 수 있는지
서버 규칙이 없어서 비공개 글이 전체 목록에 섞여 나올 수 있습니다.

**현재 웹 상태** — 크루홈 · 크루톡 목록은 항상 `아직 크루톡이 없어요`로 나옵니다.
UI 작업용 더미는 2026-10-05에 전부 제거했습니다.

### 1-2. `fetchMyActivity` 응답에 썸네일 URL 추가

중고거래 사이드바의 `최근 본 상품` · `찜 목록`이 **항상 기본 이미지**로 나옵니다.
